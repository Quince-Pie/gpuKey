Command-resource ownership continuation — 23 October 2026 UTC

Contract and result
- AV1, input/output semantics, BO ownership and GPU fences are preserved.
- AMD defaults now use context-owned adaptive hints. Tiny lists need no cache;
  growth is optional and allocation failure retains exact lookup.
- Exact maps, independent fixed tables, atomic shared hints and the old driver
  remain usable profiles. No universal performance or RAM/VRAM win is claimed.
- material/ and the original user recording are unchanged.

Performance and costs
- comparison/: first three-run matrix, before the acquire-fence addition.
  The before-acquire patches and old driver paths are retained separately.
- confirmation/: final drivers, three rotating runs per five native scenarios,
  eight-second paced/static and twenty-second saturated runs. No overlapping
  builds, profilers or other deliberate benchmark jobs. All runs have zero
  recorder skips; overloaded producer misses remain explicit. CPU/RSS/tails vary.
- core-comparison/: three rotating complete sequential helper-batch runs. The
  exact measured harness source is saved and hash-verified against inputs.sha256.
  This uses synthetic BO layout; it does not measure a full driver or queue.
- Adaptive is faster on ordinary 32–4096-entry collision-free batches; exact
  wins strongly with low-bit collisions and larger sets. At 33024 entries per
  context, exact uses 512 KiB of map payload versus adaptive's 128 KiB bound.
- samply-control/ and samply-adaptive/: actual private twelve-second captures,
  symbols and CPU summaries. Main-thread CPU 107204/121643 us; no profile speedup.
- tracy/: actual six-second, 360-frame trace, CSV zones, two decoded replay clips.
- long/: final forty-second, 2400-frame replay with two late saves, no skips,
  producer-empty callbacks, coalesced ticks or completion fallback. Independent
  full decoding passes. CPU 437.883 ms, RSS 43.953 MiB, live payload 8076263 bytes.
- Long-run sampled VRAM/GTT peaks 114.379/44.504 MiB; most VRAM samples 103.121.
  The larger peak is consistent with backed spare capacity, not a traced
  allocation diagnosis. Do not replace it with the 103.434 MiB paced-run result.

Retained invalid/intermediate checks
- core-gcc/: initial extraction compile lacked the unlikely macro.
- core-tsan/: C11 thread creation crashed the TSan runtime. pthread-based probes
  fix the harness and retain the original shared-table race as a negative control.
- native-checks/: missing _GNU_SOURCE in the initial manual graphics build.
- native-checks-corrected/: candidate EGL mixed with system Mesa GBM. GDB evidence
  and corrected consistent GBM/GL/EGL/VA configuration are retained.
- core-ordered-asan/ and core-ordered-tsan/: Clang format checking rejects %w64u.
  The final diagnostic uses an explicit unsigned-long-long conversion. Actual
  helper code and measured GCC semantics are unchanged.
